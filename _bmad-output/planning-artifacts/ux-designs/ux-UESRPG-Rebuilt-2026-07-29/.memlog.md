- (decision) Sources: PRD _bmad-output/planning-artifacts/prds/prd-UESRPG-Rebuilt-2026-07-27/prd.md, brief _bmad-output/planning-artifacts/briefs/brief-UESRPG-Rebuilt-2026-07-27/brief.md, rules coverage checklist, rules coverage decisions, and docs/ui-design-principles.md.
- (decision) Foundation: Foundry VTT 14 system UI; preserve Foundry-native document, sheet, chat, roll, combat, compendium, settings, localization, and tutorial patterns. No bespoke app layer.
- (decision) Visual direction: Morrowind-inspired homage, not direct recreation; readable during play; parchment-led light mode; carved or metallic dark mode; moderate texture; reusable tokens; UESRPG Red #5a1818 as primary system accent.
- (decision) Primary users: GMs, players, and Greybard as system/content maintainer using the same guided builders that users receive.
- (decision) 1.0 UX release gate: another UESRPG group can install, create or use required entities, run common workflows, access rights-cleared content, and recover from missing data or correction cases with minimal handholding.
- (decision) IA must cover character, statblock, item/equipment, magic entities, roll/chat output, combat, builders, GM tools, compendia/provenance, onboarding/tutorials, and validation evidence.
- (decision) Manual fallback is allowed for rare rules edge cases, custom rituals/enchantments/alchemy/unusual magic, ambiguous combat, rights-limited table text, and GM judgment, but must be visible/discoverable and must not replace core workflows.
