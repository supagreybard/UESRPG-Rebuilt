- (constraint) Source package is the BMad planning artifacts: product brief 2026-07-27, final PRD 2026-07-27, Rules Coverage Checklist and Decisions 2026-07-29, and UX Experience/Design draft 2026-07-29.
- (constraint) Brownfield project context binds implementation: Foundry VTT 14 system package, TypeScript strict runtime source, Vite ES-module build, Foundry V2 application sheets, localized UI, package metadata/build-copy alignment, no hand-edited dist.
- (decision) Adopt Foundry-native layered document architecture: package lifecycle registers document classes/data models/sheets; document/data layers own persisted state; applications prepare view context; dice/chat/workflow services perform transparent rules operations. Binds all 1.0 features and prevents a parallel SPA or bespoke state model.
- (decision) Actor and item type changes are cross-file atomic changes across constants, system.json, data models, registrations, sheets, templates, localization, styles/assets, build-copy, migration considerations, and validation. Prevents unsupported runtime document types or missing packaged assets.
- (decision) Persisted game state is mutated only through Foundry document APIs with conservative path-based updates; high-risk combat/magic/builder updates require visible confirmation or manual control. Prevents hidden or irreversible automation.
- (decision) Rules automation uses shared pure dice/rules services feeding Foundry-native chat cards; roll output must expose source, type, inputs, target, modifiers, raw roll, outcome, critical state, DoS/DoF, warnings, and adjudication notes. Prevents divergent roll math and opaque results.
- (decision) Builders are document-authoring workflows, not separate content stores: every builder creates a valid editable Foundry Actor/Item/RollTable or related document, opens it on its sheet, and supports pack compilation only when provenance allows. Prevents raw JSON as normal workflow or builder-only data.
- (decision) System content source of truth remains managed source data plus automation and a machine-readable Provenance Manifest; generated packs/dist are outputs. Prevents unclear rights state, hand-edited generated packs, and AI-content policy violations.
- (decision) UI architecture uses Foundry V2 application patterns and the UX Design/Experience spines: sheet/application classes prepare context, Handlebars renders simple localized templates, CSS tokens remain scoped to the system, and chat cards stay concise and transparent. Prevents hardcoded labels, broad global styles, and over-ornate mechanical output.
- (decision) Manual fallback is an explicit workflow state allowed only for rare edge cases, custom rituals/enchanting/alchemy/unusual magic, ambiguous combat, rights-limited content, or GM judgment; it must be visible, documentable, and must not replace core 1.0 workflows. Prevents silent failed automation.
- (decision) Lifecycle boundary follows current entrypoint: init registers public API/document classes/data models/applications/settings; setup registers trackable attributes; ready runs migrations/world-data work. Prevents world collection access before Foundry readiness.
- (decision) game.uesrpg is the only intentional module/macro public API surface; internal module paths are private unless explicitly promoted and documented. Prevents accidental integration lock-in to implementation folders.
- (decision) Release readiness architecture requires baseline typecheck, lint, build/pack compile, and manual Foundry VTT 14 validation evidence for affected sheets, workflows, packs, migrations, docs/tutorials, balanced one-shot, and minimal-handholding pass. Prevents treating build success as runtime proof.
- (version) Reality-checked existing stack from package.json/system.json/vite.config.ts: Foundry VTT compatibility 14, TypeScript ^5.8.2, Vite ^6.2.2, vite-plugin-static-copy ^2.3.0, fvtt-types GitHub main, npm package-lock workflow, package version 0.1.0.
